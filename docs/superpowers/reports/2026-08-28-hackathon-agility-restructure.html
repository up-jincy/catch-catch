목표

해커톤에서 자주 생기는 변화를 싼 변경으로 만드는 작업이었습니다. 새 데이터 붙이기, 표현 구조 바꾸기, 분석 방식 여러 개 붙이기 — 그리고 이 셋을 받치는 전제로, 흩어져 있던 실행 기록을 append-only 정본 하나로 정리했습니다.

무엇이 갈라졌나

  • 데이터 정본 — EventJournal 모든 Run 기록은 Canonical Run Event로 SQLite 저널에 먼저 커밋됩니다. SSE 스트림, 스냅샷, Artifact는 전부 파생물이고, 재시작 뒤 SSE cursor replay가 저널에서 복원됩니다. journal/
  • 분석 어댑터 — Analysis Pack 새 분석은 Pack 모듈 1개 + Registry 1줄. 방출 순서, 공개 안전성, 저장은 Kernel이 소유하고, 하니스 한 번 호출로 계약을 검증합니다. 두 번째 Pack (SourceOverviewPack)으로 검증 완료. packs/
  • 분석 어휘 — Primitive 카탈로그 14곳에 흩어졌던 Primitive 지식이 정의 1건 + 핸들러 1건으로 줄었습니다. 빠뜨리면 fail-fast와 drift 테스트가 잡습니다. domain/primitive_catalog.py, contracts/primitive-catalog.json
  • 표현 — PresentationIntent 순수 함수 프로젝터가 저널 event를 protocol 중립 Intent로 접습니다. 표현 변경은 프로젝터 교체이고, 분석 코드는 무관합니다. presentation/, GET /api/runs/{id}/presentation
  • wire 호환 격리 기존 Frontend SSE 계약은 파일 하나에 격리됐습니다. 화면 계약을 갈아엎어도 Pack과 저널은 영향이 없습니다. runtime/wire_projection.py

리뷰가 잡아낸 것

구현 뒤 리뷰어 4, 검증자 18의 적대적 리뷰를 돌려 18건 중 14건을 실제 결함으로 확인하고 수정했습니다. 대표 사례는 취소된 SQLite 트랜잭션의 고아화(저널 손상 가능), 재시작 시 터미널 상태 미조정으로 생기는 좀비 Run, 터미널 이후 cursor에서의 무한 폴링입니다. 전체 목록과 조치는 저장소 리포트에 있습니다.

남은 경계 부채

의도된 유지 — 설계 5단계(Legacy 제거) 대상

  • POST /api/runs는 아직 customer_signal 전용, 다른 Pack은 Kernel 직접 호출
  • Frontend의 domain decoder는 새 Frontend(설계 4단계) 전까지 유지
  • 코디네이터의 take_outcome 결합 1건, 하니스의 timeout/cancellation 주입 검사 미구현
