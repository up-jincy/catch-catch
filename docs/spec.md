고객 시그널 캐처(Customer Signal Catcher) 해커톤 참가신청서

1. 아이디어명

고객 시그널 캐처 (Customer Signal Catcher)

“고객은 말보다 먼저 신호를 보낸다.”

고객은 직접 의견을 남기기 전에도 이미 수많은 행동으로 자신의 니즈를 표현합니다.

앱에서 메뉴를 여러 번 탐색하고, AI검색에서 같은 내용을 다르게 검색하고, 상품 정보를 비교하고, 가입 상태를 확인하고, 필요하면 상담 채널까지 이동합니다.

하지만 이러한 행동은 서로 다른 시스템에 흩어져 있어 지금까지 하나의 고객 시그널로 연결해 활용하기 어려웠습니다.

고객 시그널 캐처는 검색·앱 행동·상담·가입정보·피드백 등 여러 채널에서 발생하는 고객 데이터를 연결하고, 자연어 질문만으로 고객의 여정과 숨겨진 니즈를 발견하여 Insight → Recommendation → Action까지 이어주는 Customer Intelligence Agent입니다.

2. 문제의 출발점

“고객이 직접 말해줄 때까지 기다려야 할까?”

고객이 명확하게 의견을 남겼을 때는 이미 여러 번의 탐색과 시도를 거친 뒤일 수 있습니다.

예를 들어 한 고객이 로밍을 준비하면서

앱 메뉴 탐색

→ AI검색에서 ‘일본 로밍’, ‘로밍 가격’, ‘4일 일본 로밍’ 반복 검색

→ 로밍 상품 상세페이지 비교

→ 가입 직전 이탈

→ 며칠 뒤 상담 채널에서 다시 로밍 문의

라는 행동을 했다고 가정해 보겠습니다.

각 시스템에서는 각각의 행동을 확인할 수 있습니다.

하지만 담당자가 실제로 알고 싶은 것은 개별 이벤트가 아닙니다.

“이 고객은 무엇을 해결하려고 했을까?”

“비슷한 행동을 하는 고객이 얼마나 있을까?”

“이 고객들에게 우리가 먼저 무엇을 제안할 수 있을까?”

현재는 이 질문에 답하기 위해 여러 데이터와 시스템을 직접 탐색하고 담당자가 데이터를 다시 연결해야 합니다.

3. Design Thinking ① Empathize

주요 사용자

고객 시그널 캐처는 고객 데이터를 기반으로 서비스를 기획하고 운영하는 다양한 실무자가 활용할 수 있습니다.

예를 들어,

CX 담당자는 여러 채널에서 나타나는 고객 경험의 흐름을 파악하고,

고객센터 운영 담당자는 상담 전후 고객 행동을 이해하고,

디지털채널 기획자와 서비스 PO는 고객이 반복적으로 탐색하거나 어려움을 겪는 여정을 발견하고,

CRM/마케팅 담당자는 특정 니즈를 가진 고객군을 찾아 적절한 메시지와 혜택을 제안할 수 있습니다.

대표 Persona — AI검색 기획자 김유진

유진은 AI검색 서비스를 담당하고 있습니다.

매일 검색량, 검색 성공률, 사용자 피드백 등의 지표를 확인하지만 이런 의문이 자주 생깁니다.

“검색 결과가 만족스럽지 않았던 고객은 그 다음에 무엇을 했을까?”

“같은 내용을 반복 검색하는 고객은 실제로 무엇을 찾고 있는 걸까?”

“검색 후 앱 메뉴를 탐색하고 상담까지 이동한 고객에게 공통점이 있을까?”

“최근 고객들이 많이 필요로 하는 정보를 우리가 먼저 보여줄 수는 없을까?”

답을 얻으려면 검색 이력만으로는 부족합니다.

검색 Agent 피드백, GA 행동로그, 가입/변경 이력, 상담 데이터 등을 각각 확인해야 하고, 고객 단위로 데이터를 다시 연결해 해석해야 합니다.

핵심 불편

“고객 데이터는 많은데, 고객의 맥락은 보이지 않는다.”

데이터는 이미 여러 곳에 존재합니다.

문제는 각각의 데이터가 하나의 고객 여정으로 연결되지 않는다는 것입니다.

4. Design Thinking ② Define

우리가 해결하려는 문제를 다음과 같이 정의했습니다.

“여러 채널에 흩어진 고객 행동을 하나의 시그널로 연결해, 고객이 원하는 것을 더 빠르게 이해하고 먼저 대응할 수 없을까?”

현재 업무는 보통 다음과 같습니다.

업무 질문 발생

→ 여러 시스템 및 Dashboard 탐색

→ 필요한 데이터 추출

→ 고객 데이터 연결

→ 패턴 분석

→ 고객 니즈 추정

→ 개선안 검토

많은 시간이 데이터를 찾고 연결하는 과정에 사용됩니다.

고객 시그널 캐처는 이 과정을

Question → Signal → Insight → Action

으로 바꿉니다.

5. Design Thinking ③ Ideate

자연어로 고객에게 질문한다

고객 시그널 캐처의 시작점은 Dashboard가 아니라 질문입니다.

AI검색 기획자가 Agent에게 질문합니다.

“최근 AI검색에서 반복해서 같은 문제를 찾은 고객들은 뭘 궁금해했어?”

또는

“AI검색 후 다른 메뉴까지 계속 탐색한 고객 여정 보여줘.”

“최근 로밍을 알아보는 고객들이 가장 많이 궁금해하는 게 뭐야?”

“AI검색에서 원하는 답을 찾지 못한 고객은 그 다음에 어디로 이동했어?”

Agent는 질문의 의도를 이해하고 관련 데이터를 가로질러 탐색합니다.

검색 이력 + 검색 피드백 + GA 행동로그 + 가입정보 + 상담 데이터

↓

고객별 행동 연결

↓

유사 Journey 및 Segment 발견

↓

고객 니즈 해석

↓

Insight 생성

↓

다음 Action 추천

사용자가 자연어로 궁금한 내용을 질문합니다.

STEP 2. Catch

이처럼 개별 시스템에서는 단순한 로그였던 행동을 하나의 Customer Journey로 재구성합니다.

STEP 3. Understand

Agent가 유사 행동을 하는 고객을 묶어 하나의 Segment로 해석합니다.

발견된 Customer Signal

“단기 일본 여행을 준비하며 적합한 로밍 상품을 결정하지 못한 고객”

예: 328명

주요 행동

가격/데이터량 비교

상품 상세페이지 이동

가입까지 연결되지 않음

일정 기간 후 동일 주제 재검색

Agent Insight

고객들은 단순히 ‘로밍’ 정보를 원하는 것이 아니라, 여행 기간과 목적지에 맞는 상품을 빠르게 결정하고 싶어 하는 것으로 보입니다.

7. Insight에서 끝나지 않는 Agent

고객 시그널 캐처가 단순한 분석 Dashboard나 AI Report와 다른 지점입니다.

Agent는 발견한 시그널을 바탕으로 다음 행동까지 제안합니다.

Agent Recommendation

해당 고객군에는 일반적인 ‘로밍’ 검색어보다 여행 상황을 반영한 추천 검색어를 먼저 노출하는 것이 효과적일 것으로 보입니다.

추천 검색어 후보

일본 4일 로밍 추천

일본 여행 로밍 가격 비교

내 여행에 맞는 로밍 찾기

그리고 향후 실제 AI검색 운영 시스템과 연결되면,

[추천검색어 적용하기]

를 통해 Agent가 해당 고객 Segment에 노출되는 추천 검색어를 직접 설정할 수 있습니다.

즉,

Insight를 알려주는 AI

에서 끝나는 것이 아니라

고객을 이해하고 → 대응 방법을 제안하고 → 실행까지 대신하는 Agent

로 발전합니다.

8. Agent의 역할

고객 시그널 캐처는 다음 5단계로 동작합니다.

① Explore

질문과 관련된 여러 고객 데이터 탐색

② Connect

검색·앱·가입정보·상담 등 서로 다른 채널의 고객 행동 연결

③ Understand

행동의 맥락을 해석하고 유사한 고객 Journey와 Segment 발견

④ Recommend

발견된 고객 니즈에 맞는 서비스 개선 또는 선제 대응안 제안

⑤ Act

실제 운영 시스템과 연결하여 추천검색어, 콘텐츠, CRM Target 등의 실행까지 수행

Explore → Connect → Understand → Recommend → Act

11. Design Thinking ⑤ Test

MVP를 통해 세 가지 가설을 검증합니다.

가설 1

자연어 질문만으로 고객 데이터를 탐색할 수 있다면 분석 업무 시간이 줄어든다.

기존의 Dashboard → 데이터 추출 → 연결 → 분석 과정을 Question → Insight로 단축합니다.

가설 2

여러 채널의 고객 행동을 연결하면 개별 데이터에서는 보이지 않던 고객 니즈를 발견할 수 있다.

단순 검색량이 아니라 검색 전후 앱 탐색, 상품 이용 상태, 상담 행동까지 연결하여 고객 행동의 맥락을 파악합니다.

가설 3

Insight를 실제 업무 Action으로 연결하면 Agent의 실무 활용 가치가 높아진다.

분석 결과를 읽고 다시 운영 시스템으로 이동하는 것이 아니라 Agent가 실행 가능한 Action을 제안하고 수행하도록 합니다.

12. 기대 효과

첫째, 고객 분석 업무 생산성이 향상됩니다. 여러 시스템과 Dashboard를 직접 탐색하지 않고 자연어 질문으로 고객 행동과 니즈를 확인할 수 있습니다.

둘째, 고객이 명시적으로 의견을 표현하기 전에 니즈를 발견할 수 있습니다. 반복 검색, 메뉴 이동, 비교 행동, 가입 여부 등 작은 행동을 하나의 시그널로 연결합니다.

셋째, 데이터 활용의 진입장벽을 낮출 수 있습니다. CX, 고객센터, 디지털채널, PO, CRM/마케팅 등 다양한 실무자가 복잡한 분석 방법을 몰라도 고객 데이터를 활용할 수 있습니다.

넷째, 분석과 실행 사이의 간극을 줄일 수 있습니다. 발견된 Segment와 Insight를 추천검색어, 콘텐츠, CRM Target 등 실제 고객 경험 개선으로 바로 연결할 수 있습니다.

13. Future Vision — Enterprise Customer Intelligence Agent

MVP에서는 AI검색 기획자의 하나의 Use Case를 보여주지만 고객 시그널 캐처의 최종 모습은 특정 서비스에 한정되지 않습니다.

CX 담당자

“최근 고객들이 반복적으로 해결하려는 문제는 뭐야?”

→ 주요 Customer Journey와 개선 영역 제안

고객센터 운영 담당자

“상담 전에 고객들이 어떤 경로를 거쳐 들어오는지 알려줘.”

→ 상담 전 Customer Journey 분석 및 Self-care 개선안 제안

디지털채널 기획자 / PO

“로밍 가입 과정에서 고객이 가장 오래 고민하는 부분이 뭐야?”

→ 주요 Journey와 개선 UI/콘텐츠 제안

CRM / 마케팅 담당자

“최근 해외여행을 준비하는 것으로 보이는 고객군 찾아줘.”

→ Segment 생성 및 적절한 CRM Action 제안

그리고 Agent는 점차 사람이 질문하기를 기다리지 않고 먼저 이야기합니다.

“최근 일본 여행을 준비하는 고객들의 로밍 비교 행동이 증가하고 있습니다.”
