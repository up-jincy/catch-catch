Customer Intelligence Agent 해커톤 참가신청서

1. 아이디어명

Customer Intelligence Agent
흩어진 고객 데이터를 자연어로 탐색하고, 고객 문제와 비즈니스 기회를 찾아주는 AI Agent

고객은 말보다 먼저 신호를 보낸다
"고객 시그널 캐처" (Customer Signal Catcher)

2. 해결하고 싶은 업무 문제

고객에 대한 데이터는 이미 사내 여러 시스템에 충분히 축적되어 있습니다.

사용자 검색 이력

검색 Agent 사용자 피드백

GA 대표채널 행동로그

모바일 가입별 통합 내역 및 이력

고객센터 VOC/STT 상세 이력

하지만 실제 업무에서는 데이터가 시스템별로 파편화되어 있기 때문에, 고객이 어떤 문제를 겪었고 어떤 행동을 거쳐 현재 상태에 이르렀는지를 한 번에 파악하기 어렵습니다.

예를 들어 CX 담당자가

“최근 인터넷 해지 가능성이 높은 고객은 누구이며, 왜 그렇게 판단할 수 있을까?”

라는 질문에 답하기 위해서는 검색로그, 앱 행동로그, 가입정보, VOC 등을 각각 조회하고 데이터를 직접 연결해야 합니다.

또한 개별 시스템에서는 각각의 행동은 확인할 수 있지만,

검색 실패 → 반복 탐색 → 고객센터 문의 → 해지 검색

처럼 서로 다른 채널에서 나타나는 고객 행동의 연속성을 파악하기 어렵습니다.

결국 고객 데이터를 분석하기 위해 많은 시간이 소요되고, 담당자의 경험과 직관에 따라 분석 수준에도 차이가 발생합니다.

Customer Intelligence Agent는 이러한 문제를 해결하기 위해 고객 데이터를 자연어로 탐색하고, 여러 데이터 간 관계를 AI가 분석하여 고객의 문제·위험 신호·기회와 다음 액션까지 제안하는 업무 지원 Agent입니다.

3. Design Thinking 기반 문제 정의

① Empathize : 현업 담당자는 어떤 어려움을 겪고 있는가?

주요 사용자

CX / 고객경험 기획자

디지털 서비스 기획자 및 PO

고객센터 운영 담당자

CRM / 마케팅 담당자

상품 및 서비스 운영 담당자

Persona

김유진 / CX 기획자 / 7년차

유진은 최근 특정 서비스의 VOC와 해지율이 증가했다는 이야기를 듣고 원인을 분석해야 합니다.

하지만 정확한 고객 행동을 확인하려면 각각 다른 시스템에서

고객센터 VOC 조회

앱 행동로그 조회

검색이력 조회

가입 상품 및 변경 이력 조회

Agent 피드백 조회

를 수행해야 합니다.

데이터를 조회한 이후에도 각각의 데이터를 시간순으로 연결하고 의미를 해석해야 합니다.

결국 몇 명의 고객 사례나 일부 VOC를 확인한 후 원인을 추정하는 방식으로 분석하게 됩니다.

Persona의 주요 불편

“데이터는 많은데, 고객에게 실제로 무슨 일이 있었는지는 알기 어렵다.”

“고객 행동을 이해하려면 여러 시스템을 돌아다녀야 한다.”

“데이터를 찾는 것보다 데이터를 연결하고 해석하는 데 더 많은 시간이 든다.”

“어떤 고객부터 대응해야 하고 무엇을 해야 하는지도 결국 사람이 판단해야 한다.”

4. Define : 우리가 해결해야 하는 핵심 문제

현업의 핵심 문제는 단순히 데이터 조회가 어렵다는 것이 아닙니다.

현재 업무 방식

질문 발생

↓

각 시스템별 데이터 조회

↓

Excel / SQL / Dashboard 등으로 데이터 확인

↓

담당자가 데이터를 연결

↓

고객 행동 원인 추정

↓

업무 대응안 도출

즉, 많은 업무 시간이 데이터 탐색과 해석 과정에 사용되고 있습니다.

우리는 다음과 같이 문제를 정의했습니다.

“고객 관련 업무 질문이 발생했을 때, 담당자가 여러 시스템을 직접 탐색하지 않고도 고객 데이터를 가로질러 필요한 정보와 인사이트를 얻을 수 없을까?”

5. Ideate : Customer Intelligence Agent

Customer Intelligence Agent는 사용자가 자연어로 업무 질문을 입력하면 여러 고객 데이터를 탐색한 것처럼 분석하여 답변을 제공하는 Agent입니다.

예를 들어 담당자가 질문합니다.

“최근 인터넷 해지 가능성이 높은 고객 찾아줘.”

“AI검색에서 해결하지 못하고 고객센터까지 문의한 고객이 얼마나 돼?”

“최근 고객들이 가장 반복해서 해결하려고 한 문제가 뭐야?”

Agent는 고객 행동을 주제별로 분류하고

7. 주요 사용 Flow

STEP 1. 자연어 질문

첫 화면에는 Search / Chat Interface를 제공합니다.

사용자는 별도의 SQL이나 데이터 조회 과정 없이 업무 질문만 입력합니다.

STEP 2. Agent 데이터 탐색

질문 입력 후 Agent가 어떤 데이터를 분석하고 있는지 시각적으로 보여줍니다.

예:

고객 데이터를 분석하고 있습니다.

✓ 검색 이력 분석
✓ Search Agent 피드백 분석
✓ 앱 행동로그 분석
✓ 가입/변경 이력 분석
✓ VOC/STT 분석

이를 통해 단순 ChatGPT가 아니라 사내 데이터를 직접 탐색하는 Agent라는 인상을 제공합니다.

STEP 3. Insight 제공

예를 들어

“최근 인터넷 해지 가능성이 높은 고객 찾아줘.”

12. 기대 효과

① 업무 생산성 향상

여러 데이터 시스템을 탐색하는 시간을 줄이고 자연어 질문만으로 필요한 정보를 확인할 수 있습니다.

② 고객 문제 조기 발견

검색, 앱 행동, VOC 등 각각의 데이터에서는 발견하기 어려운 고객의 반복 행동과 위험 신호를 Cross-channel 관점에서 발견할 수 있습니다.

③ Data Democratization

SQL이나 분석 도구에 익숙하지 않은 서비스 기획자와 운영 담당자도 고객 데이터를 직접 탐색할 수 있습니다.

④ 선제적 고객 대응

VOC가 발생한 이후 대응하는 방식에서 벗어나,

반복 검색, 탐색 실패, 상담 전환과 같은 Early Signal을 발견해 고객 문제에 선제적으로 대응할 수 있습니다.

13. 향후 확장 방향

MVP에서는 자연어 기반 고객 데이터 분석을 중심으로 구현하지만 향후에는 전사 Customer Intelligence Platform으로 확장할 수 있습니다.

예를 들어 Agent가 매일 고객 데이터를 모니터링하며

“이번 주 인터넷 품질 관련 해지 신호가 전주 대비 증가했습니다.”

“로밍 가입 고객 중 인증 단계에서 반복 이탈이 발생하고 있습니다.”

“AI검색에서 해결하지 못하고 고객센터로 이동하는 고객이 증가했습니다.”

와 같이 사람이 질문하기 전에 문제를 발견하는 Proactive Agent로 발전할 수 있습니다.

또한 분석 결과에서 실제 업무 실행까지 연결하여

Insight → CRM Target 생성 → 상담 / 캠페인 / 서비스 개선

으로 이어지는 Agentic Workflow로 확장할 수 있습니다.

14. 한 문장 아이디어 소개

Customer Intelligence Agent는 검색·앱·VOC·가입정보 등 흩어진 고객 데이터를 자연어로 탐색하고, AI가 고객 행동의 맥락을 연결해 문제와 위험 신호, 다음 업무 Action까지 제안하는 Agent입니다.

15. 핵심 메시지

고객 데이터는 이미 충분히 존재합니다.

문제는 데이터가 부족한 것이 아니라,

각각의 데이터가 서로 연결되지 않은 채 존재하고 있다는 것입니다.

Customer Intelligence Agent는

“데이터를 어디에서 찾아야 하지?”

라는 업무를

“고객에게 지금 무슨 일이 일어나고 있지?”

라는 질문으로 바꿉니다.

그리고 그 질문에 대해

데이터 → 고객 Journey → Insight → Action

까지 연결하는 것이 우리가 만들고자 하는 Agent입니다.
